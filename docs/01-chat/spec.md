# Sirius-Agent（终端流式对话）Spec

## 背景

用户要做一个类似 Claude Code 的命令行 AI 编程助手 Sirius-Agent（Python 实现）。本阶段是 Sirius-Agent 从零开始的第一个里程碑：实现一个可交互的终端对话程序——启动后进入 TUI，用户输入问题，AI 流式打字机式返回回答，支持多轮对话（有上下文记忆），底层可在 Anthropic Claude 与 OpenAI 两种 API 协议间切换，用 YAML 配置文件管理供应商信息。后续阶段才会加 tool use、文件操作、代码编辑等 agent 能力。

## 目标

- 验证 Provider 抽象层设计，为以后接入更多模型供应商打基础
- 打通"配置 → 选择供应商 → 流式请求 → TUI 渲染"的最短闭环
- 得到一个日常可以直接用来聊天的命令行工具

## 功能需求

- F1: 用户在终端运行 `sirius-agent` 命令后，进入交互式对话循环（REPL），可以连续输入多轮消息
- F2: 每次用户输入一条消息后，Sirius-Agent 调用配置的 LLM API，并将回复以流式（SSE）方式逐字符/逐块打印到终端，而不是等待全部生成完再显示
- F3: Sirius-Agent 在对话过程中保留本次会话中此前的所有消息（用户输入与 AI 回复），并在每次请求时把历史上下文一并发送给模型，使 AI 能记住之前说过的话
- F4: 支持通过 YAML 配置文件定义一个或多个 LLM 供应商配置，每个配置含 `name`、`protocol`、`model`、`base_url`、`api_key`、`thinking` 六个字段
- F5: Sirius-Agent 支持 Anthropic 协议和 OpenAI 协议两种后端协议，配置文件的 `protocol` 字段决定实际使用哪种协议与对应 API 通信
- F6: 启动时可以通过命令行参数指定使用哪个供应商配置（按 `name` 匹配）；不指定时默认使用配置文件中的第一个供应商
- F7: 启动时可通过命令行参数指定配置文件路径；不指定时默认读取当前目录下的 `sirius-agent.yaml`
- F8: 当所选供应商的 `protocol` 为 Anthropic 且配置中 `thinking` 字段开启时，Sirius-Agent 调用 Claude 的 extended thinking 能力，并将模型返回的思考过程与正式回答以不同样式流式展示给用户
- F9: YAML 配置中的 `api_key` 字段支持 `${ENV_VAR}` 占位符语法，启动时从对应环境变量读取真实密钥；同时也允许直接写明文值
- F10: Provider（供应商协议）层对上层调用暴露统一接口，新增一种协议后端时不需要改动 TUI 或对话主循环代码
- F11: 用户可以通过明确的命令或按键退出对话循环，程序正常退出

## 非功能需求

- N1: 流式输出的首字节到终端显示的延迟应尽量小，不应等待整个回复生成完毕才开始输出
- N2: 配置文件缺失必需字段、协议不支持、或供应商 `name` 找不到匹配项时，程序应给出清晰的错误提示后退出，而不是抛出未处理异常堆栈
- N3: API 请求失败（网络错误、鉴权失败、限流等）时，应向用户展示可读的错误信息，并允许用户继续下一轮输入，而不是直接崩溃整个程序
- N4: 代码需要有中文注释（遵循项目 CLAUDE.md 约定）
- N5: 使用 uv 进行依赖管理，项目可通过 uv 安装依赖并运行（Python 解释器由用户自行安装，不要求 uv 自动拉取）

## 不做的事

- 不做 tool use / function calling
- 不做文件读写、代码编辑等 agent 能力
- 不做多会话管理与历史持久化到磁盘（本阶段仅内存级多轮记忆，进程退出即丢失）
- 不做除 Anthropic、OpenAI 外的其他协议后端（如本地模型、Gemini 等）
- 不做配置文件的多级/分层加载（如项目级 + 用户级合并）
- 不做鉴权重试、自动重连、断线续传等高级网络容错机制
- 不做 Web UI 或桌面 GUI
- 不做 Python 版本自动管理（用户自行保证本地 Python 环境）

## 验收标准

- AC1: 运行 `sirius-agent`（无参数），程序读取当前目录 `sirius-agent.yaml` 的第一个供应商配置并进入交互式对话界面
- AC2: 用户输入一句话回车后，终端逐字/逐块流式打印出 AI 回复，而非一次性整段出现
- AC3: 用户连续进行至少 3 轮对话，AI 的回复能正确引用/呼应更早轮次提到的信息（证明上下文记忆生效）
- AC4: 将配置文件 `protocol` 分别设为 `anthropic` 和 `openai` 并各自配置对应 `base_url`/`api_key`/`model` 后，两种情况下均能成功完成一次完整的流式对话，无需修改任何代码
- AC5: 使用 `sirius-agent --provider <name>` 指定配置文件中存在的某个供应商 `name` 时，程序使用该供应商而非第一个
- AC6: 使用 `sirius-agent --config <path>` 指定一个非默认路径的配置文件时，程序从该路径加载配置
- AC7: 当所选供应商 `protocol` 为 `anthropic` 且该配置项 `thinking: true` 时，对话过程中能看到模型的 thinking 内容以不同于正式回答的样式流式展示出来
- AC8: 配置文件中 `api_key` 写成 `${SOME_ENV_VAR}` 形式，且对应环境变量已设置时，程序能正确读取到真实密钥并完成鉴权请求
- AC9: 故意提供一个错误的 `api_key` 触发鉴权失败，程序打印可读错误信息而不崩溃退出，并能继续接受下一轮输入或正常退出
- AC10: 故意提供一个格式错误/缺字段的配置文件，程序打印清晰错误提示后退出（而非未处理异常堆栈）
- AC11: 用户输入退出指令（如 `/exit` 或 Ctrl+D）后，程序正常退出，返回 shell
