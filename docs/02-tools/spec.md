# Sirius-Agent（工具系统）Spec

## 背景

Sirius-Agent 第一期已经交付了纯聊天能力：流式对话、多轮记忆、双协议切换（Anthropic/OpenAI）、extended thinking 展示。但模型目前只能"动嘴"——回答问题，不能对本地环境做任何实际操作。这一期要给它装上工具系统，让模型能读写文件、执行命令、搜索代码，从聊天机器人升级为能干活的 Agent 雏形。

## 目标

- 提供统一的 Tool 抽象，六个核心工具（读文件、写文件、改文件、执行命令、按模式找文件、搜代码内容）都实现这个抽象
- 提供工具注册中心，集中管理工具、按名查找、转换成两种 protocol 各自认得的工具描述格式
- 模型可以在一轮对话中请求调用工具（可并行调用多个），系统执行后把结构化结果（含错误）喂回给模型，模型据此给出这一轮的最终文字回复——到此为止，不做连续多轮的自动工具调用循环（那是下一期 Agent Loop 的范围）
- 工具执行有明确的安全边界（文件操作限制在工作目录内）和健壮性保证（超时、异常都不能让程序崩溃，而是转成清晰的结构化错误反馈给模型）

## 功能需求

- F1：系统提供统一的 Tool 抽象，每个工具需声明名称、描述、参数 Schema，并提供执行方法
- F2：系统内置六个工具：读文件（read_file）、写文件（write_file）、改文件（edit_file）、执行命令（execute_command）、按模式找文件（glob_files）、搜代码内容（grep_content）
- F3：系统提供工具注册中心，可按名称查找工具，并能把已注册的工具列表转换成 Anthropic / OpenAI 各自 API 所需的工具描述格式
- F4：用户提问后，模型可以在回复中请求调用一个或多个工具（同一轮内允许并行调用多个）
- F5：系统执行模型请求的工具调用，对每次执行做超时控制和异常捕获，统一封装成结构化结果（成功 / 失败 + 内容）返回
- F6：工具调用记录与执行结果会被加入对话历史，系统自动向模型发起一次后续请求以获得最终文字回复；这一轮到此结束，不做二次工具调用循环
- F7：edit_file 通过"待替换文本在文件中唯一出现"来定位替换位置；未匹配到或匹配到多处时都不修改文件，并返回清晰的错误信息说明具体原因
- F8：读文件、写文件、改文件、按模式找文件、搜代码内容这五个工具，解析路径后必须落在启动时的工作目录内；超出范围时拒绝执行并返回清晰错误
- F9：execute_command 执行命令时带超时限制；超时或命令以非零退出码结束，都以结构化失败结果返回，不让程序崩溃
- F10：模型调用工具时，终端展示工具名、调用参数、执行结果摘要，与已有的 thinking / 正式回答样式区分开
- F11：Anthropic 和 OpenAI 两种 protocol 的 Provider 都要支持工具调用——组装阶段把注册中心的工具列表传给模型，解析阶段要能从流式响应中识别工具调用意图（包括拼接分片返回的 JSON 参数）

## 非功能需求

- N1：工具执行失败（文件不存在、权限不足、命令出错等）返回给用户的错误信息必须是可读的自然语言描述，不能暴露原始 Python 异常堆栈
- N2：任意单次工具执行失败或抛出未预期异常，都不能导致整个 Sirius-Agent 进程崩溃——必须以结构化错误结果收场，对话循环继续可用
- N3：execute_command 的超时阈值要有明确默认值（默认 30 秒），超时后能可靠终止子进程，不留下僵尸进程或让程序卡死
- N4：新增工具系统不能破坏第一期已验收的纯聊天能力——不带工具调用的普通对话行为应与之前完全一致

## 不做的事

- 不做连续多轮的自动 Agent Loop（模型拿到工具结果后自己决定要不要继续调用下一个工具，直到任务完成）——这是下一期的范围
- 不做工具执行前的用户确认 / 权限弹窗——六个工具这一期全部自动执行
- 不做六个核心工具之外的更多工具（网络请求、git 操作、代码执行沙箱等）
- 不做跨调用的持久 shell 状态——execute_command 每次都是独立的新子进程，不维护 cwd/环境变量在多次调用间的延续
- 不做工具调用的可视化 diff（比如 edit_file 展示修改前后对比）——这次只展示结构化的执行结果摘要
- 不做工具调用历史的磁盘持久化——延续第一期"纯内存对话历史"的设定

## 验收标准

- AC1：要求模型读一个存在的文件，模型调用 read_file 拿到内容并在最终回复中正确体现文件内容
- AC2：要求模型创建一个新文件并写入指定内容，操作后该文件在磁盘上真实存在且内容与预期一致
- AC3：要求模型修改文件中某一段在文件里唯一出现的文本，edit_file 正确定位并替换，文件内容按预期变化
- AC4：对文件中出现多次的文本执行 edit_file，返回清晰的"匹配到多处"错误，文件内容不被改动
- AC5：对文件中不存在的文本执行 edit_file，返回清晰的"未找到匹配"错误，文件内容不被改动
- AC6：要求模型执行一个命令（如列出目录），execute_command 正确执行并把 stdout 与退出码返回，模型在回复中引用了执行结果
- AC7：执行一个耗时超过超时阈值的命令，execute_command 能在超时后正确终止并返回超时错误，不卡死整个程序
- AC8：要求模型查找匹配某种模式的文件（如所有 `.py` 文件），glob_files 返回正确的文件列表
- AC9：要求模型搜索代码里包含某关键字的位置，grep_content 返回正确的匹配文件与位置信息
- AC10：尝试通过路径穿越（如 `../../etc/passwd` 或工作目录之外的绝对路径）访问工作目录外的文件，被拒绝并返回清晰错误，不实际发生任何读写
- AC11：同一轮对话中，模型调用工具并拿到结果后，程序自动追加一次请求得到最终文字回复；整个过程（工具名、参数、结果、最终回复）在终端上依次可见，无需用户手动催促
- AC12：把 protocol 切换为 openai 后，以上工具调用相关场景（AC1-AC11 可执行的子集）同样正常工作，不改代码只改配置
- AC13：工具执行内部抛出未预期异常时，程序打印清晰错误、不崩溃，且能继续下一轮正常对话（普通聊天不受影响，呼应 N4）
